## 一、这份数据在测什么

把 MIPLIB 的混合整数规划（MIP）实例，**改写成一个二次无约束二值优化（QUBO）问题**，再用**迭代消元模拟退火（SA）**求解，最后把解还原回原始变量空间，**独立校验**约束是否满足，并与 MIPLIB 官方最好已知解算 **gap**。

三条对照路线（同一批实例）：

| 路线 | 说明 | 状态 |
|---|---|---|
| strict（严格编码） | 用 e_K 精确表示约束违反，无松弛变量、无编码误差 | 会跳过部分行 |
| 松弛编码（binary/unary） | 加松弛变量 + 平方罚项，全覆盖 | 变量/耦合爆炸 |
| **hybrid（本次）** | 每侧先试 strict，失败自动回退松弛兜底，**一行不跳** | 已完成 7 实例 |

另有一条正在后台跑的 **CBC/LP 热启动**实验（见第六节）。

## 三、术语表（每个缩写/专名 + 解释）

### 3.1 问题与数据

| 术语 | 解释 |
|---|---|
| **MIP** | Mixed Integer Programming，混合整数规划：目标线性、约束线性、部分变量必须取整数 |
| **MIPLIB 2017** | 公认的 MIP 基准实例库（学术界统一的"考卷"），`miplib2017-v36.solu` 存官方目标值 |
| **MPS** | Mathematical Programming System，求解器通用的实例文本格式，含 ROWS/COLUMNS/RHS/BOUNDS 四段 |
| **n / m / nnz** | 变量数 / 约束行数 / 非零系数个数（nnz = number of nonzeros） |
| **`=opt=` / `=best=`** | 官方值的两种标签：`=opt=` 已证明最优；`=best=` 是至今最好的**可行**解（未必最优） |
| **gap** | 相对间隙 = (本解目标 − 参照值)/\|参照值\|×100%。最小化问题上：正=比已知最好解差；**负=比已知最好解"还好"，实际几乎必然说明本解不可行**（不可行解可以随便"更好"） |
| **可行 / 违反行数** | 还原到原始变量空间后，逐行算 LHS（左侧和）是否落在 [lb, ub] 内；超出的行数就是违反行数 |
| **LP 松弛（LP relaxation）** | 把整数约束 x∈{0,1} 放松成 0≤x≤1 的线性规划，可多项式时间求解，给出最小化问题的**下界** |

### 3.2 求解器

| 术语 | 解释 |
|---|---|
| **HiGHS** | 开源高性能 LP/MIP 求解器，是 `scipy.optimize.linprog` 的默认后端；本实验用它算 LP 界 |
| **CBC** | Coin-or Branch and Cut，开源 MIP 求解器，由 `python-mip` 自带；本实验用它出可行解 |
| **分支切割（Branch and Cut）** | MIP 精确算法：分支定界 + 割平面，限时后会返回当前最好可行解 |
| **incumbent** | 求解器当前持有的最好可行解（限时停止时就是它返回的解） |
| **presolve / 预处理** | 求解前的模型化简（固定变量、加强行等）。sorrell7 上预处理吃掉 75s 而没找到解，所以热启动实验里关掉了它 |
| **warm start / 热启动** | 用一个已知（近似）解作为算法的起点，而不是从零随机开始 |
| **MIP start** | 求解器接口层面的热启动，把初始解喂给 CBC 等求解器 |

### 3.3 QUBO 编码

| 术语 | 解释 |
|---|---|
| **QUBO** | Quadratic Unconstrained Binary Optimization，二次无约束二值优化：min xᵀQx + hᵀx，x∈{0,1}^n。约束只能以**罚项**形式进入 |
| **HUBO** | 高阶（≥3 次）伪布尔多项式，是编码约束时的中间产物 |
| **罚项 / λ（罚权）** | penalty / penalty weight：把"违反约束"折算成能量代价。λ 太小→解不可行；λ 太大→能量被罚项主导，目标函数失去梯度（本实验 ramos3 正是后者） |
| **松弛变量（slack variable）** | 把不等式 Σa_i x_i ≤ b 变成等式 Σa_i x_i + s = b 的辅助变量 |
| **unary / binary 松弛** | 松弛量 s 的两种二进制表示：unary 用权 1,1,1,…（需 S 个变量）；binary 用权 1,2,4,…,余项（只需 ≈log₂S 个）。二者都能精确表示 0..S |
| **e_K / 初等对称多项式** | 编码"Σ w·v ≥ K 是否成立"的**精确违反指示函数**：0/1 变量下取值严格为 0/1，没有松弛误差。K 是阈值 |
| **超立方体下三角编码** | e_K 的一种展开方式（只枚举"恰好 K 个被选"的组合），本项目的 strict 路线 |
| **K** | 判定违反的阈值；K 越大，需要的单项式越多（K 是这套编码的复杂度主参数） |
| **单项式 / 项数（terms）** | 展开后的非零项个数。项数随 K 指数增长，是内存/时间爆炸的根源（circ10-3 有侧项数达 143 万，全实例合计 4.84 亿项） |
| **canonical / 规范化** | 把一侧约束整理成"系数全正 + 阈值 K"的标准形（含补变量 1−x 的替换） |
| **GCD 归一化** | 系数同除最大公约数 g：`≤` 侧取 ⌊C/g⌋+1、`≥` 侧取 ⌈R/g⌉，可行域不变但 K 变小，能救回一部分行 |
| **Rosenberg gadget** | 把三次项 xyz 精确改写成二次项的标准技巧：引入辅助变量 w，加罚项 λ(xy − 2xw − 2yw + 3w)；w 最优取值恰为 x·y |
| **二次化（quadratization）** | 把 HUBO 彻底降成 QUBO 的过程（本项目用 Rosenberg gadget + 堆实现） |
| **辅助变量（aux）** | 二次化引入的额外二元变量，不属于原问题；本实验 ramos3 用了 28431 个 |
| **strict / full / 兜底（fallback）** | strict=逐侧 e_K 直构；full=完整下三角 + Pascal 逆变换（K 受限更严）；兜底=该侧退化成"松弛变量 + 平方罚项" |
| **QuboGraph** | 项目内部的稀疏图结构：邻接表存二次项，支持"固定变量后消元缩图" |

### 3.4 求解算法

| 术语 | 解释 |
|---|---|
| **SA（模拟退火）** | Simulated Annealing：以温度 T 接受劣解的随机搜索，T 逐步降低，最终收敛 |
| **Metropolis 准则** | 劣解接受概率 exp(−ΔE/T)；T 高时敢冒险，T 低时近乎贪心 |
| **冷却 schedule（cooling）** | 温度下降曲线（指数/线性/S 型）；本项目三种轮流用 |
| **reheat（重加热）** | 每隔若干步把温度抬回起点的一半，用来跳出局部最优 |
| **迭代消元（iterative elimination）** | 本项目主干：每轮在当前子图上跑多次 SA → 统计每个变量的**投票** → 高共识变量**固定**并从图中消元 → 缩图 → 下一轮 |
| **vote / 共识度 conf** | 每次 SA 对每个变量投 0/1 票；conf = max(0/1 占比)，越接近 1 越一致 |
| **consensus threshold（阈值）** | conf ≥ 阈值(0.92，含自适应偏移) 的变量才被固定；无人达标时触发"死锁"处理（全部按多数票固定） |
| **boost（指数增强）** | 按变量重要性缩放系数，让强约束更"硬"，本实验 alpha=1.0 |
| **LNS** | Large Neighborhood Search，大邻域搜索：只解一个子集上的子问题。本项目有 `lns_improve.py`，本次实验未启用 |

## 四、逐实例解读

### sorrell7 — 表现最好的"标准型"实例
- 结构：2048 个 0/1 变量、78848 行、目标系数全为 −1（等价于"最大独立集/集合打包"：每行本质是 Σx≤1）。
- 编码：78848 侧**全部**严格编码（K=2，每行两两配对的罚项），QUBO 与原始问题几乎同构（0 松弛、0 辅助），只有 39424 个耦合。这正是 strict 编码的理论最优情形。
- 求解：180s、23 轮投票 → 目标 −165（Σx=165），但仍有 64 行被违反，gap 16.7%。
- 关键参照：LP 界 = −1024（LP 最优解是"全部 x=0.5"，Σx=1024）→ **LP 松弛对集合打包类极弱**，整数最优只有 Σx=198，LP 却说 1024 可行。

### f2000 — 相对最优
- 10488 侧严格编码（K=3/4），仅 12 侧连兜底都建不出（残留边界）。辅助变量 5542 个（K=4 需要 gadget），QUBO 9542 变量 / 29919 耦合。
- 结果：目标 1986 vs 纸面 1810，**gap 9.72%（全表最好）**，但 846/10500 行违反。

### circ10-3 — 编码主战场
- 42620 行有效：28575 侧严格 + 14495 侧兜底（14336 侧因 K 超限/项数超 cap 被拒），得 26160 变量 / 363586 耦合。
- 构建从早先的 **>40 分钟 / 9.3GB 内存**压到 **96–104 秒**：靠 DP 项数预筛 + 每侧 100 项上限 + 每侧 aux 预算 + 堆版 Rosenberg 二次化。
- 求解：SA 有效时间只有 44s（大 QUBO 单轮就超预算），目标 507 vs 256，gap 98%，2813 行违反。

### ramos3 — "罚项吞掉目标函数"的典型
- 全部 2187 行走兜底（K=15→ 项数爆炸），2187 行 × 每行 4 个松弛变量的 binary 松弛 = 8748 松弛变量 + 28431 辅助，QUBO 30618 变量（耦合只有 84264，比 binary 路线的 251505 稀疏得多）。
- 结果：**严格可行（0 违反）但目标 1937 vs 纸面 186，gap 941%**。SA 能量 −59243 的量级说明：能量几乎全由罚项构成，一旦拿到可行解，目标函数的梯度被淹没，SA 没有动力继续优化目标。
- 另有口径疑点：`solutions/ramos3.sol` 记 `=obj= 220`，而 `miplib2017-v36.solu` 记 `=best= 186`，两者不一致，建议核对（可能是目标符号/常数项口径不同）。

### d20200 / t1722 — 兜底路线下彻底失败
- d20200：1502 行无一侧能严格编码（K=8–20 但项数巨大），1302 个二元松弛变量 → 4483 变量 / 442347 耦合。SA 169s 后 684/1502 行违反；"gap −90%" 是**不可行解刷出的假象**。
- t1722：338 行全兜底，且**松弛变量为 0**（这些是等式行，兜底路径对等式不加松弛变量，只加平方罚项），36630 变量 / **1939.7 万耦合**。SA 246s 只跑了 1 轮就超时，320/338 行违反。
- ex1010-pi：1467 行中只有 1 侧严格；9484 松弛变量 → 34691 变量 / 386.9 万耦合。SA 196s、2 轮，只剩 1 行违反（最接近可行），但目标 7076 vs 233 完全跑偏。

## 五、三条核心结论

1. **编码管线已端到端可用**：hybrid 策略做到 0 跳过行、小规模穷举验证精确、hybrid 与纯 strict 在全覆盖时逐元素一致。工程性能也有量级提升（circ10-3：40 分钟/9.3GB → 100 秒/内存平稳）。
2. **编码质量决定上限**：严格侧占比 100%/99.9% 的 sorrell7、f2000 得到 QUBO 与问题近乎同构，SA 表现最好（gap 9.7%/16.7%）；严格侧为 0 的大 K 实例（ramos3/d20200/t1722/ex1010-pi）退化为纯惩罚法，180–250s 内多数连可行解都拿不到。
3. **失败有三种可区分的机制**，不能混为一谈：
   - **罚项量级失衡**（ramos3）：可行但目标被罚项淹没；
   - **预算/轮数不足**（t1722 只跑 1 轮、ex1010-pi 只跑 2 轮、circ10-3 只跑 5 轮）：大 QUBO 单轮投票就吃掉全部预算；
   - **gap 口径陷阱**（d20200 −90%、ex1010-pi 2937%）：不可行解的 gap 无意义，**必须先看违反行数再看 gap**。

## 六、CBC/LP 热启动实测结果（`run_warm_sa.py` → `warm_results.md`）

流程：LP 松弛（HiGHS，floor/nearest/ceil 三取整按（违反行,目标）选优）/ CBC 限时 60s（关 presolve + `FEASIBILITY`）/ 官方 `.sol` → 解嵌入 QUBO 空间（松弛变量按"恰好消违"贪心、Rosenberg 辅助取 `lit(n1)·lit(n2)`、自由变量贪心压罚）→ cold/lp/cbc/sol 四源在**同预算 180s、同种子 42** 下对比。热启动票=低温局部精修（温度 ×0.05、占比 100%、不翻转初值）。

格式：gap% / 违反行数（负 gap 同样表示解不可行）。

| 实例 | cold | warm-lp | warm-cbc | warm-sol |
|---|---|---|---|---|
| sorrell7 | 26.3% / 违84 | 74.2% / 违26 | 20.2% / 违4 | **0.000% / 可行** |
| f2000 | 9.7% / 违846 | 53.9% / 违1049 | 无 CBC 解 | 19.1% / 违460 |
| d20200 | −90.2% / 违684 | −66.9% / 违159 | **1.37% / 违65** | 2.57% / 违77 |
| ramos3 | 941% / 可行 | 714% / 可行 | 105.9% / 可行 | **18.28% / 可行** |
| circ10-3 | 98.0% / 违2813 | **18.36% / 违339** | 无 CBC 解 | 87.9% / 违312 |
| ex1010-pi | 2937% / 违1 | 352.8% / 可行 | 5.150% / 可行 | **2.575% / 可行** |
| t1722 | −90.3% / 违320 | 123.4% / 违42 | CBC 原生崩溃 | **4.857% / 可行** |

### 结论

1. **热启动是这套 QUBO 编码的必要组件，不是可选优化。** 冷启动 180s 在 7 个实例里只有 ramos3 拿到可行解；换一个 60s 的 CBC 起点，ex1010-pi 从 2937% 掉到 5.15%、d20200 从 −90.2%（不可行）掉到 1.37%。
2. **三路来源强弱稳定**：`warm-sol`（上界控制组）> `warm-cbc`（实用）> `warm-lp`（最弱）。`warm-sol` 只证明"给定最优解，低温精修能保住"（sorrell7 逐比特复现、t1722 零翻转）；真正有价值的是 `warm-cbc`——**它不需要任何已知解**，60s CBC + 180s SA 就给出 1.4%~20% 的 gap。
3. **LP 取整是最弱一路**：集合打包类（sorrell7）LP 顶点是"全 0.5"，取整必然大规模违反；更根本的是 LP 界本身极弱（sorrell7 界 −1024 vs 整数最优 −198），界与解质量都不可依赖。
4. **热启动保住"可行域附近"但不保证可行**：d20200(65)、circ10-3(339)、f2000(460)、t1722 的 lp(42) 仍有违反行。这些实例的症结在兜底罚权与被松弛掉的行结构，热启动只能缓解不能根治——下一步应标定兜底罚权 λ_r。
5. **口径补充**：t1722 的 `solutions/t1722.sol` 给 114245，而 `=best=` 是 108953，`.sol` 里的解不等于最优（warm-sol 的 4.86% gap 因此是相对 108953 算的）。

### 工程事故与加固

t1722 在 CBC 的 MIP 分支定界阶段让整个 Python 进程崩溃（`cbc_logs/t1722.log` 为 0 字节；`mip` 是 C 扩展，Python `try/except` 拦不住原生段错误），导致第一轮 7 实例实验在最后一个实例上中断、报告未落盘。已加固：

- 结果增量落盘 `warm_rows.json`，每个实例跑完立即刷新 `warm_results.md`
- 新增 `--report-only`（只按 json 重生成报告）
- 新增 `rebuild_warm_rows.py`：从 `warm_run.log` 正则重建结果行（本次已恢复 6 实例 22 行）
- LP / CBC 块各自 `try/except`，CBC 失败回退缓存解 `cbc_<name>.npy`
- t1722 改为跳过 CBC（`--sources cold,lp,sol`）单独续跑
